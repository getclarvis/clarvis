# Support

Clarvis is prerelease open-source software maintained on a best-effort basis. There is currently no
paid support channel or response-time guarantee.

## Choose the right channel

- **Setup or usage question:** open the
  [question form](https://github.com/getclarvis/clarvis/issues/new?template=question.yml).
- **Reproducible defect:** open the
  [bug form](https://github.com/getclarvis/clarvis/issues/new?template=bug.yml).
- **Product idea:** open the
  [feature form](https://github.com/getclarvis/clarvis/issues/new?template=feature.yml).
- **Suspected vulnerability:** follow [SECURITY.md](SECURITY.md) and report it privately.
- **Provider billing, quota, account, or model availability:** contact that provider. Clarvis may
  display identity or model entitlement returned by a connected subscription, but it cannot manage
  provider billing, quotas, eligibility, or account settings.

Before reporting a problem, run `clarvis --version`, try `/doctor` in the TUI, and consult the
[troubleshooting guide](https://clarvis.dev/operations/troubleshooting). A useful report includes the
installation method, operating system and architecture, terminal or multiplexer, exact steps,
expected behavior, actual behavior, and a minimal project when one can be shared safely.

Do not post `~/.clarvis/keys.json`, `~/.clarvis/subscriptions.json`, API keys, tokens, private
prompts, proprietary code, or unsanitized diagnostic files. Reduce a report to the smallest safe
example first.
