# Self-configuration authority

Only an eligible entry agent in Host or Sandbox placement can receive the host's protected-file mutation reviewer. Builtin tools must be enabled and the run's immutable grant ceiling must permit editing. A custom Agent Profile, this skill, or a shell approval cannot create that port or widen its scope. Container guests cannot write host configuration through this route.

Use ordinary file tools for admitted global or workspace `.clarvis` documents, including standalone skills under `.clarvis/skills`, and for skills or plugins under `.agents`. Clarvis settings, Agent Profiles, Extension Profiles and workflows belong only under `.clarvis`; credentials are private global Clarvis state and are not agent-authored. The host classifies each target as authoring, operational or private and validates supported document formats before commit. Private state, credentials, trust records, unsafe links and unrecognized destinations are refused. Review Off still enforces those limits. Review Auto uses authenticated operator evidence and Judge; Review On asks about the concrete proposed effect. A session decision covers only its shown effect, target and authority scope, and expires with that session. A refusal does not authorize another path or shell fallback.

In Sandbox, file tools prepare changes inside the isolated environment and the host commits only reviewed configuration batches. A mixed patch may also include ordinary files inside the writable workspace. A read-only workspace stays read-only, including when temporary directories contain it. Container and child agents cannot use the host configuration writer.
